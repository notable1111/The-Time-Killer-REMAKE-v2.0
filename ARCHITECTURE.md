# Architecture

How the systems of The Time Killer Remake connect. Update this file whenever a system is added or changed.

## Principles

- **Research first, then act — always.** Measure the thing you are about to change, *in the place it actually lives*, before changing it. Check the API before calling it, look at the asset before judging it, render in the real scene before tuning for it. This is the rule this project has paid for most often:
  - The hit VFX was tuned against an isolated neutral backdrop and *darkened* for "palette match". In the real castle it covered **0.26% of the screen and vanished in 0.75s** — invisible. Nobody rendered it in-scene until after it shipped.
  - Blood droplets were drawn without once placing them beside the wardrobe. They came out at **saturation 0.93 / value 165** against game art measuring **0.07 / 52** — candy-red gumballs on muted pixel art. One `git`-free minute of comparison would have caught it.
  - `TextureSheetAnimation.startFrame` was set in *frames* because the ScriptReference example uses a 0–7 slider. Unity 6 clamps it to **0–1**; the docs example is from an older version. It only surfaced because a value read back as `0.9999` instead of the `6` that was written.
  - `Setup/22` and `Setup/25` destroyed and rebuilt their whole rig on every run, silently deleting a `DamageSfx` object nobody put back. It had been that way for months because nobody diffed the scene before and after.
  - **Corollary:** when you catch yourself about to eyeball something twice, build the measurement instead. `TimeKiller/Verify/VFX Visibility` exists because "does this read?" is a number, not an opinion — and a number is repeatable by the next person.
- **Heavy architecture, small pieces:** single-purpose components; every tunable number lives in a ScriptableObject config (`C#/<Feature>/Configs/`), never hardcoded.
- **Event-driven:** systems talk through the Core event bus, not direct references. A system should compile even if the systems it talks about don't exist yet.
- **Input ≠ logic:** input reading is a separate layer from character/system behavior, so a second player (future co-op) or an AI can drive the same character code.
- **State machines** for anything with modes (player movement, enemy AI, game flow).
- **Editor setup scripts** (menu `TimeKiller/Setup/...`) create and wire scene objects — scenes are never hand-authored YAML.
- **Swappable content, removable features:** any asset (character, sounds, sprites) must be replaceable by editing configs only — never code; and any feature component (e.g. footsteps) must be removable from its object without breaking the others. Don't switch content until the full replacement asset set is ready.

## Systems

### Core (`C#/Core/`, namespace `TimeKiller.Core`)
- **GameBootstrap** — runs before the first scene loads (`RuntimeInitializeOnLoadMethod`), clears static state, spawns the persistent `[TimeKillerCore]` object. No scene setup needed — the game boots itself.
- **EventBus** — static typed publish/subscribe (`EventBus.Publish(new SomeEvent{...})`). The only sanctioned way for systems to talk across features.
- **AudioDucking** — a single shared dial (`World`, 0..1) that the *atmospheric* audio voluntarily multiplies into its own volume. There is no mixer to pull down, and `AudioListener.volume` is useless here because it would take the heartbeat with it. `PlayerHeartbeat` writes it; `AudioDirector` reads it. Voluntary on purpose: footsteps deliberately opt out, because muting the feedback you steer by reads as a bug rather than as tension, and if the writer is deleted the dial simply stays at 1.
- **ServiceLocator** — registry for long-lived services (`Register<T>` / `Get<T>`).
- **StateMachine + IState** — reusable state machine driven by `Tick`/`FixedTick`.
- **GameFlow** — the shape of one run: `RunPhase{Playing,Won,Lost}`, the run timer, the `Time.timeScale` freeze on the ending beat, **R** to restart (full scene reload — the only reset that can't leak stale state) and **Esc** to quit. Knows nothing about clocks or maniacs: features end a run by publishing `RunEndedEvent{Won, Headline}`, and an optional `GameFlow.ProvideSummary(Func<string>)` hook lends the end screen a one-line objective summary. Scene object built by `Setup/29`, which also registers the scene in Build Settings (restart is a `LoadScene`).
- **RunEndScreen** — the win/lose canvas (uGUI, sortingOrder 900). Fades on `unscaledDeltaTime` because the game itself is frozen; shows headline, `survived m:ss · X / N clocks fixed`, and the restart prompt.
- **WorldNoiseEvent** (`WorldEvents.cs`) — noises made by the *world* rather than by the player's feet (the gate crashing open; future props, glass, traps). `{Position, Loudness, AlwaysHeard}`; each listener decides whether it hears it, so nothing here depends on the Maniac feature existing.
- **DebugOverlay** — F1 overlay: FPS + any values features register via `DebugOverlay.Watch(label, getter)`. Compiled out of release builds.
- **CoreConfig** (SO) — overlay tunables. Asset: `C#/Core/Configs/CoreConfig.asset`.

### Player (`C#/Player/`, namespace `TimeKiller.Player`)
Flow: `IInputSource` → states → `PlayerMotor` → `Rigidbody2D`.
- **IInputSource / KeyboardInputSource** — input abstraction (WASD + Shift via Input System). Co-op or AI drivers implement the same interface.
- **PlayerController** — composition root; owns the state machine (Idle/Walk/Run in `PlayerStates.cs`), publishes `PlayerStateChangedEvent`.
- **PlayerMotor** — accel/decel toward target velocity on `Rigidbody2D` (gravity 0, top-down).
- **PlayerFacing** — 4-direction facing, publishes `PlayerFacingChangedEvent` (animation hooks onto this).
- **PlayerMovementConfig** (SO) — speeds and responsiveness. Asset: `C#/Player/Configs/PlayerMovementConfig.asset`.
- **PlayerAnimationDriver** — listens to state/facing events, tells `SpriteAnimator` (Core) which clip to play. Playback speed is normalised against the speed the *current* clip depicts (walkSpeed for a real walk cycle, runSpeed otherwise) so the feet stay planted. States it does not know about fall back to idle; `RepairState` is matched **by string, not `nameof`**, deliberately — the player must not hold a compile-time reference to the removable Objectives feature.
- **PlayerAnimationSet** (SO) — maps state+facing → clips. Asset + generated clips: `C#/Player/Configs/`. `walk[8]` and `repair[8]` are optional: packs without those sheets leave them empty and `GetWalk`/`GetRepair` fall back to the run clip slowed / to idle. Every accessor falls back to *something*, so a missing pack can never render an empty sprite.
- **PlayerController.CurrentState / IsFreeToInterrupt** — the seam features use to take the player over. A feature only pushes its own state when `IsFreeToInterrupt` (Idle/Walk/Run), and only hands control back if `CurrentState` is still its own — so two features can never fight over returning the player to Idle. Facing is likewise only driven by input while `IsFreeToInterrupt`, otherwise WASD would spin a locked player's pose on the spot.
- **Character art** — the player is the PixelLab "Survivor" (hooded, faceless, 29px) in `Assets/Resources/Assets/Characters/Survivor/`, built by `Tools/CharArt/build_sheets.py` and imported by **Setup/33** (run it OUT of play mode — in play mode its scene-attach step cannot mark the scene dirty and silently half-completes). Sheets: `Idle`, `Walk`, `Run`, `Repair`, plus `Rotation` as the single-frame idle fallback, ×8 directions. The world's scale contract: **32 pixels per world unit, 29px characters, feet 17px below the sprite pivot** — match all three or a new character looks pasted in, or out-scales the maniac. Setup/5 still rebuilds the older New_Leaf placeholder.
- **Gait cadence** is authored in `SurvivorAnimationSetup`, not guessed per clip: `WalkStepsPerSecond 4.5` / `RunStepsPerSecond 6` (→ 18 and 24 fps on 8-frame cycles), with `fps = frames × steps ÷ 2` because one cycle is two foot contacts. They **must differ** — one shared rate (the original `frames × 1.75`) turned the legs over at the same speed whether you sneaked or sprinted. The numbers come from the art: the side-view strips depict a 0.41u walk stride and a 0.48u run stride, so zero sliding would need 5.4 and 9.3 steps/s; that is a blur at run, so we take most of the correction (sliding ~17% walk, ~35% run) rather than all of it.
- Scene setup: menu `TimeKiller/Setup/4 - Create Player In Scene` (slices Adventurer sheets, creates configs, builds the Player object + top-down camera), then `5 - Generate Player Animations`.

### Sprite animation (in Core)
- **SpriteAnimationClip** (SO) — frames + fps + loop + `eventFrames` (foot contacts etc.), generated from sliced sheets.
- **SpriteAnimator** — plays clips on a SpriteRenderer; swap clips mid-play preserving phase; `SetSpeed` for live velocity-matched playback; fires `FrameReached` on event frames. Reusable for enemies/props.

### Footsteps & stealth noise (Player)
- **PlayerFootsteps** — on each foot-contact frame: plays a random Kenney step sound (pitch-jittered, quiet walk / loud run) and publishes `PlayerFootstepEvent{Position, IsRunning, Loudness}`. Enemy hearing consumes this event — audio volume and stealth noise are the same number by design. What actually separates sneaking from sprinting is **loudness, not rate**: `ManiacPerception` hears a step only within `hearingRadius × loudness`, i.e. 9×0.3 = **2.7u walking** vs 9×0.85 = **7.65u running**. Contact frames are measured, not assumed — frames `[2,6]` of the 8-frame cycles are where the art's legs actually reach full spread (verified by `TimeKiller/Verify/Probe Player Animations`).
- **PlayerFootstepConfig** (SO) — step clips + walk/run loudness + pitch jitter.
- Animation playback speed follows real velocity (`PlayerAnimationDriver.Update`), facing uses stickiness hysteresis (`PlayerFacing`) to prevent diagonal flicker. Camera: tight horror framing (ortho 2.4), follow deliberately deferred.
- Setup: menu `TimeKiller/Setup/6 - Setup Footsteps + Tight Camera` (after 4 and 5).

### Camera (`C#/Camera/`, namespace `TimeKiller.CameraSystem`)
- **v2 = Cinemachine rig** (menu `TimeKiller/Setup/12`): `CM_PlayerCamera` (CinemachineCamera + PositionComposer + Confiner2D) follows the **CameraTarget** child of the Player. `CameraTargetDriver` drifts that child toward the direction the character faces (look-ahead). `CameraBounds` polygon hard-confines the view to the hall — extend its path (or add per-room bounds) when the map grows. `CinemachineConfigSync` pushes `CameraConfig.asset` values (view size, damping) into Cinemachine every frame — tune the ONE asset, in edit or play mode.
- **CameraFollow** — legacy v1, kept on the Main Camera but disabled (fallback: disable CM objects, re-enable it). Setup: menu `TimeKiller/Setup/10`.
- All knobs in `CameraConfig.asset`: viewSize (zoom 1.5–8), smoothTime, lookAheadDistance/Speed.

### Lighting & depth (`C#/Lighting/`, namespace `TimeKiller.Lighting`)
- URP runs the **2D Renderer** (`URP_2DRenderer.asset`) with Y-axis transparency sorting: same-order sprites sort by world Y — lower on screen renders in front. Player and props share order 0 under SortingGroups, so walking behind/in front of objects just works.
- **Light2D setup** (menu `TimeKiller/Setup/11`): dark global ambient, warm flickering torch lights (`FlickerLight2D` — layered Perlin noise), soft player glow. All sprites use Sprite-Lit-Default; shadow/shade sprites stay unlit so light can't wash them out.
- **Contact shadows**: baked gradient strips at wall bases + blob shadows under props.
- **Cast 2D shadows** (`ShadowConfig` + `ShadowSetup`, menu `TimeKiller/Setup/49`, removal `49b`, audit `TimeKiller/Verify/Shadow Audit`). Added 2026-08-03, because the scene had **zero** `ShadowCaster2D` and every `Light2D` had `shadowsEnabled = false` — light passed through every wall and prop. 58 casters take their shape **live from the existing colliders** via URP's internal `ShadowShape2DProvider_Collider2D` (reflection, verified against URP 17.4.0, fails loudly on a version change) rather than baking an outline, because the colliders are hand-tuned and a baked shape would silently go stale. Three things a future change must respect: `ShadowCaster2D` is `[DisallowMultipleComponent]`, so an object with several colliders (HallColliders has seven) needs a `__Shadow_N` child per extra or those colliders cast nothing; the LDtk import puts an empty `CompositeCollider2D` on every tilemap layer, so casters are gated on `pathCount > 0` or the floor itself would shadow the room; and torch strength must be written to `FlickerLight2D.baseIntensity`, not just `Light2D.intensity`, or Play mode overwrites it every frame.
- **Shadow detail pass** (2026-08-04, same config and menu). Four levers, all per-category or per-light: **penumbra** (`shadowSoftnessFalloff`, URP's untouched 0.50 default → 0.80, so a shadow is crisp at the caster's foot and dissolves as it stretches); **volume** (props `CastAndSelfShadow` so they have a lit and a dark side, walls deliberately `CastShadow` because a wall shading its own face fights the torch lighting it); **breathing** (`FlickerLight2D` drives `shadowSoftness` from the *same* Perlin value as the intensity — it lives in that component precisely so it cannot drift out of step with its own flame); and **the maniac's tell** (`maniacShadowScale`, his caster on a scaled `__Shadow_Body` child so his shadow reaches your view before he does — measured at 1.00u footprint against the player's 0.45u). Two traps live here: a `ShadowConfig.asset` already on disk keeps its serialized values and silently beats a changed field default, and `Remove()` must zero `shadowBreathAmount` or it switches a shadow feature on while removing shadows.
- **`ShadowMesh2D.bounds` is degenerate** — it reports size 0 for a perfectly working caster. Measure a shadow shape from `mesh.vertices`, never from its bounds; `ShadowAudit.ShapeWidth()` does this.
- **Judge lighting in Play, never in the editor viewport.** Measured 2026-08-03 through the real game camera: changing a `Light2D` **property** from a script in edit mode does not reach the rendered frame at all — `shadowsEnabled`, `castsShadows`, intensity 1.1→20, and Multiply→Additive each moved **0.000% of pixels**. Only adding or removing lights outright registers. Any editor-screenshot measurement of lighting is therefore fiction, which is why `Shadow Audit` is structural and reports data rather than a coverage percentage.
- All 25 lights currently use the **Multiply** blend style: they scale the sprite's own colour toward full albedo rather than adding light, so they saturate and extra intensity stops doing anything.

Listens for `PlayerHitEvent` on the bus (attackers never reference the player), applies damage + invulnerability window + shove impulse away from the source + red hit-flash, publishes `PlayerHealthChangedEvent` / `PlayerDiedEvent`. v1 death rule (placeholder until save/death design): respawn at spawn with full HP.

### Maniac (`C#/Maniac/`, namespace `TimeKiller.Maniac`)
The killer. Design (interview 2026-07-22, v1.1 playtest 2026-07-23, AI overhaul 2026-07-24): hearing+sight hybrid, patrols the wing loop, chase FASTER than player run (5.2 vs 4.5) balanced by a generous lose-sight timer; catch = 1 HP hit + shove. His high-level decisions now come from a **utility-AI brain** (see ManiacBrain) and his movement from **grid A\* pathfinding** (see Navigation). **He never stops:** a swing costs him only 0.35s recovery — the cooldown runs while chasing. **The escape is the player's job:** post-hit adrenaline (**1.55× for 4s**, in PlayerHealthConfig) + invulnerability (2.2s) + ghost-through (player↔maniac collision off for 2.5s after a landed hit — his unpushable mass-400 body can't pin a cornered player; collision restores once separated). Flow: `ManiacPerception` (senses) → `ManiacBrain` (decides) → states → `ManiacNavigator`/`ManiacMotor` → `Rigidbody2D`.
- **ManiacController** — composition root; owns the state machine (Patrol/Investigate/**Search**/Chase/Attack in `ManiacStates.cs`) but **the `ManiacBrain` chooses which state runs** each frame (Attack + the Outlast wardrobe-march stay reactive). Publishes `ManiacStateChangedEvent`, aims the sight cone along movement.
- **ManiacBrain** (utility AI) — scores every behavior from weighted considerations (line of sight, time-since-seen, noise recency × proximity) + a stickiness bonus; highest wins. Replaces hard-coded transitions, so behavior *emerges* from competing scores (a fresh noise pulls him off a search). States are now pure behaviors. Pure `Score()` is unit-testable; F1 overlay "Brain" shows live P/I/S/C scores. Weights in `ManiacConfig` "Brain".
- **ManiacPerception** — hearing: subscribes `PlayerFootstepEvent`, heard when distance < loudness × hearingRadius (running is loud — the stealth choice); records `LastNoiseTime` for the brain's recency score. **Walls muffle it (2026-08-02)** — until then hearing was the only sense that ignored geometry, so a footstep through solid stone arrived exactly as loud as one beside him. Each solid body on the line multiplies the surviving radius by `hearingWallMuffle` (0.45), through the same `sightBlockers` mask his eyes use. Measured over 733 posts in CastleWingLDtk: **11.7% of his running earshot removed overall, median post 2.6%, up to 89.8% in the tight interior** — a scalpel on the "he heard me through a wall" moment, not a general nerf. Walking is nearly unaffected (0.7%) because walking earshot is only 2.7u. Collider *count* is a floor, not a thickness (a merged `CompositeCollider2D` reports one hit for many walls) — chosen because under-counting fails toward the old behaviour, never toward a deaf maniac. `hearingWallMuffle = 1` restores the old model exactly, and a test asserts that escape hatch still works. Sight: range + cone + LinecastAll that walls block (self/player/triggers filtered). Publishes `ManiacHeardNoiseEvent` / `ManiacSpottedPlayerEvent`.
- **ManiacMotor** — destination steering on Rigidbody2D, same accel/brake pattern as PlayerMotor. Low-level; navigation now comes from `ManiacNavigator` (see Navigation).
- **ManiacNavigator** (see Navigation system) — obstacle-aware movement; Patrol/Investigate/Search/wardrobe-march call `Nav.MoveTo` so he paths *around* walls/pillars. Active chase still uses breadcrumbs when sight is lost, and a straight beeline while he can see you — **with a stall watch behind it (2026-08-02)**. "I can see you" does not imply "I can walk there": sight is a centre-to-centre linecast and his body is 0.57u wide, so a doorway seen at an angle passes the line and stops the body. `TimeKiller/Verify/Maniac Chase Grind` measured **9.46% of all sightings blocked, rising to 18.28% at 6-7u — i.e. worst exactly at `sightRange`, the moment he first acquires you**. Rather than predict which sightings those are, `ChaseState.Beeline` watches his own **displacement** (velocity lies — the motor writes `linearVelocity` directly, so a body pressed into a wall reports full speed) and hands over to `Nav.MoveTo` for `beelineNavSeconds` when he covers under `beelineStallFraction` of the predicted ground. Same destination either way, so a false positive is free. The navigator has a route for **100% (318/318)** of the blocked cases the probe found — checked before the fallback was trusted.
- **ManiacBreadcrumbs** — chase navigation: records the player's positions while visible; he follows the trail through the same doorways the player used (the trail is always reachable, so no pathfinding needed mid-chase).
- **SearchState + PlayerBeliefMap** — losing sight starts a *reasoned* hunt, not a fixed sweep. `PlayerBeliefMap` is a probability field: seeded at the last-seen cell + biased forward along `ManiacPerception.LastSeenDirection` (the flee direction), it spreads to walkable neighbours each Step and COLLAPSES cells he can currently see (Observe) — belief flows away from where he's already looked. SearchState paths (via the A* navigator) to the highest-probability cell, scans, picks the next; he never re-checks cleared areas. The brain still owns *when* to give up. Pure (walkability + LOS are delegates) → unit-testable.
- **ManiacPatrolRoute** — waypoint loop object (gizmo-drawn). The servant passage is deliberately NOT on the route — the player's blind-spot escape.
- **ManiacConfig** (SO) — every tunable: speeds, hearing radius, sight range/cone, lose-sight seconds (the balancing valve), attack damage/range/cooldown, patrol pacing. Asset: `C#/Maniac/Configs/ManiacConfig.asset`.
- Scene setup: menu `TimeKiller/Setup/20 - Create Maniac In Scene` — REFUSES to run without the Nightmare Slashers pack under `Outsource/NightmareSlashers` (no invisible enemies / no placeholder art). Animation slicing pass comes once the killer look is picked from the pack.

### Escalation (`C#/Maniac/ManiacEscalation.cs`) — the run gets worse as you win it

The answer to the measured problem the hesitation pass could not fix. Over 407 recorded seconds the tension curve was **Panic 44.3% · Safe 26.8% · Aftershock 20.5% · Unease 5.7% · Threat 2.7%** — the run is either safe or a chase, and the *build* is 8% of it. Stretching the moment of being caught made that moment ~5x longer without filling the band in. The horror-design research names the same thing as the genre's core back-half failure, "escalation through new elements is absent", and this game had the purest form of it: **the third clock was mechanically identical to the first.**

- **The seam is `WorldProgressEvent` in Core, not `ClockFixedEvent`.** Subscribing the maniac to an Objectives event would mean deleting that folder stops the Maniac feature compiling — the coupling the removability rule exists to prevent, and the reason `ManiacHintEvent` already lives in Maniac rather than in the Director that sends it. `ObjectiveManager` publishes both: `ClockFixedEvent` answers "which clock, and where", `WorldProgressEvent` answers "how far through the run are we". Any future objective — a ritual, a fuse box — escalates him for free by publishing it, with no edit to the Maniac feature.
- **Three dials, all identities at their neutral value.** Patrol/investigate/search **speed** ×1.15, **hearing** ×1.25, **wardrobe check chance** +0.18 at 100% of the objectives, blended in over `blendSeconds` 6 so the castle tightens a few seconds after the clock lights up rather than snapping. `enabled = false`, or 1/1/0, reproduces the pre-escalation maniac exactly.
- ⚠️ **What is deliberately NOT escalated, and why.** *Chase speed* is already 5.2 against the player's 4.5 — escalating it does not make the run tenser, it removes the escape. *Sight range* is the fairness dial; hearing is escalated instead precisely because hearing is the sense the player **controls** (walk and you are quiet again). *Damage* is 3 HP with no healing. Also exempt: the **suspicious creep** (`suspiciousApproachSpeed`), which is the 2026-08-04 hesitation beat and is only a beat because it is slow, and the **search rush**, which already equals his chase speed.
- ⚠️ **`moveSpeedAtFull` has a hard ceiling of ×1.22.** Patrol 1.8 against the player's walk 2.2: above that, keeping quiet distance from a patrolling maniac requires *running*, which is the loud choice, and escalation would have deleted the endgame's stealth layer instead of tightening it. Shipped at 1.15 → **2.07 measured live**. `ManiacEscalationTests` pins it and `Setup/51` prints it every run.
- ⚠️ **Two bonus sources now stack on the wardrobe.** The Director caps what the player can *teach* him at 0.35 so hiding can never become useless; escalation adds a second source, so that promise had to be re-made about the **sum** — `ChanceWithCeiling` holds base + taught + escalation under `maxWardrobeChance` 0.6. Without the component the ceiling is 1 and the arithmetic is byte-for-byte the old `Clamp01`.
- **Auto-added by `ManiacController` with `HideFlags.DontSave`**, so every maniac in every already-built scene gets it with **no scene edit** and nothing to re-run. Consequence worth knowing: `FindObjectsByType` **cannot see it** — reach it through `ManiacController.Escalation`, or subscribe to `ManiacEscalatedEvent`, which exists so telemetry never has to poll.
- Config self-loads from Resources (the `AudioMix` contract): deleting the asset is the uninstall. Setup: `TimeKiller/Setup/51`, which never overwrites an existing config. F1 line `Escalate`; the wardrobe line now prints its live chance.
- **Verified 2026-08-27:** compiles, `SmokeCheck ok:true`, 51/51 EditMode tests (13 new). Runtime: baseline identity (`MoveSpeed 1`), then `WorldProgressEvent{3,3}` → Intensity 0→1, patrol **1.8→2.070**, hearing **9→11.25u**, wardrobe chance **0.12→0.30**. **Not yet playtested by ear — this is a difficulty change and needs the user's ruling before it is locked.**

### Director (`C#/Director/`, namespace `TimeKiller.Director`) — the second brain
Modelled on **Alien: Isolation's two-brain split** (research 2026-08-03): a *director* that always knows where the player is and periodically points the creature at their AREA, and the creature itself, which knows nothing and must use its own senses. The director never hands over the position — it only steers. That is why that game reads as tense rather than as cheating.

- **The problem is measured, not theoretical.** A recorded bot session ran **80 seconds with zero detections**. When the maniac loses you his belief map decays, he returns to patrol, and the encounter is simply over. No amount of sense-tuning fixes that, because nothing existed to bring him back.
- **ManiacDirector** — issues a `ManiacHintEvent` after `hintAfterQuietSeconds` of genuine quiet (he must be **Unaware**, at least `minHintDistance` away, and past `minSecondsBetweenHints`), so it rescues dead time rather than piling onto something already happening. The hint is a **smeared point + radius**, and the error grows the longer he has been clueless.
- ⚠️ **`hintError` (9u) vs `sightRange` (7u) is the dial that keeps this honest.** If the error ever drops below the sight range, arriving at a hint *becomes* finding the player and the Director is cheating whatever the code claims. `Setup/45` prints the comparison every run. **Nothing in the feature writes awareness, `LastSeenPosition` or belief.** Verified live: hint landed 17.2u from the real position, he travelled 31.7u→7.1u to it, then found the player himself (Unaware→Detected, Patrol→Chase, 4.3u).
- **He learns from what the player DOES, never from dying.** Hides the player actually got away with (`foundWhileHiding` false) raise the wardrobe check chance past `hidesBeforeLearning`, capped by `maxWardrobeBonus` 0.35 so hiding can never become useless. Isolation gates behaviours on player metrics for the same reason: gating on *deaths* would punish losing, which is the one thing that reads as unfair. Consumed by `ManiacWardrobeSearch.EffectiveCheckChance`.
- **Doubt** — `ManiacConfig.searchDoubtChance` (0.3) makes SearchState take the second or third likeliest belief cell via `PlayerBeliefMap.RankedTargetBeyond`. A searcher who always walks to the optimum reads as a pathfinder, not a person. **`rank: 0` is byte-for-byte the old behaviour**, so 0 disables the feature exactly.
- ⚠️ **`ManiacHintEvent` and `ManiacLearnedEvent` live in the MANIAC feature, not here.** Declared in Director, deleting that folder would stop the maniac compiling — precisely the coupling the removability rule exists to prevent. Director depends on Maniac; Maniac depends on nothing. Delete the object and he behaves exactly as before. Setup: `TimeKiller/Setup/45`. F1 line `Director`.

### Navigation (`C#/Navigation/`, namespace `TimeKiller.Navigation`) — grid A* pathfinding
Obstacle-aware movement so the maniac routes around walls/pillars instead of grinding into them. Removable: without a `ManiacNavigator`, states fall back to direct `Motor.MoveTo`.
- **WalkabilityGrid** — samples the physics world into a walkable/blocked grid at **node points aligned to the world integer lines** (0.5 spacing). Alignment is load-bearing: this map's wall colliders are thin strips sitting ON integer coords, so a coarse grid sampling half-integer cell centers misses them. Blocked = a static non-trigger collider overlaps (ALL layers — walls live on several); dynamic bodies (player/maniac) and triggers (camera zones) filtered out. Also stores a **clearance field** (2026-07-25): multi-source BFS out of every blocked cell, so each cell knows its distance to the nearest wall. Built *after* the reachability flood-fill, so the dropped outside-the-castle void correctly counts as wall.
- **GridPathfinder** — A* (binary-heap open set + lazy deletion, ~0.2ms/query) + line-of-sight "string pull" → a few natural straight-line world waypoints. **Body-width aware** (2026-07-25) — this is what stopped characters scraping walls, and both halves are cost/refusal only, so no route can ever be lost:
  - The string pull used to test a **hairline**: one cell-wide Bresenham between waypoints. A diagonal shortcut whose *centre* clears a corner still drags a real body through it. Measured against live physics with the maniac's own collider: of 1852 shortcuts the hairline accepted, **70 (3.8%) were physically impossible** — those were the grinding. The test now demands the agent's body width; a refused shortcut simply keeps the corner, i.e. falls back to raw A* cells, which are body-safe by construction. Same sample: **0 of 1013 impossible**.
  - A* had no reason to stay off walls (hugging cost exactly what the middle cost, and diagonals made hugging *cheaper*). A small penalty on low-clearance cells now buys the corridor centre. It is a **cost, not a block**, so a one-tile doorway is still used when it is the only way. Octile heuristic stays admissible — the penalty is never negative. 300 random routes after the change: **0 null paths, 0 crossing a blocked cell**.
  - `bodyRadius` is **not** the same number as the grid's sampling `clearance`: the first asks "can I walk *through* there", the second "can I stand *here*". Converting a radius to cells must add half the sample box, because the real wall surface can sit that much nearer than the blocked node's centre.
- **ManiacNavigator** (on the maniac, auto-added by ManiacController) — `MoveTo(dest, speed)` paths + feeds `ManiacMotor` one waypoint at a time, repaths on move/interval; falls back to direct on an unreachable target. `Rebuild()` re-samples (call when the layout opens — doors; **nothing calls it yet** — the bot handles the gate by rebuilding its own `BotPath`). Tunables: clearance, bodyRadius, repath distance/interval, waypoint tolerance.
- **NavDebugView + INavDebugSource** (2026-07-25, dev-only — compiled out of release like DebugOverlay) — **press F3 in play mode** to cycle through every registered body (**Player → Maniac → off**) and paint its own picture of the map in the *game* view: red **a real collider** · grey **no collider, but cut off from the reachable region** (the outside-the-castle void — ~79% of a typical map, and painting it like a wall is why the screen used to read as mostly solid) · **yellow walkable-but-too-tight-for-this-body** · green open · cyan current route. **Read the legend for whose body it is:** on CastleWing, 186 cells — 4.9% of where the player can walk — are red on the *maniac's* map (his sample box 0.85 vs the player capsule 0.55), and all 186 are merely yellow on the player's own. Red always means "for the body named", never "for anybody". `PlayerNavDebug` (in `C#/Player/`, attached at runtime by `PlayerController` so no scene or prefab can drift) supplies the player entry and builds its grid **on first view**, not at startup — ~33k overlap queries is not a cost to pay for a key you may never press. Yellow is the whole point: "walkable" and "walkable by a body this wide" are different questions and every wall-scraping bug lived in the gap between them. Each agent paints its own colours because each has its own body. Registration is push-based (agents register themselves) so Navigation never learns which characters exist — **a new AI joins the cycle for free**; the host GameObject creates itself on first registration, so there is nothing to add to a scene. Unlit on purpose: the scene is lit by URP 2D lights, and a lit overlay is black in exactly the dark corners worth inspecting.

### Fear (`C#/Fear/`, namespace `TimeKiller.Fear`) — one number every tension channel answers to
`FearConductor` computes a single smoothed 0..1 `fearLevel` and publishes `FearChangedEvent`; `PlayerHeartbeat`, `PlayerBreathing`, `FearDrone`, `FearSting` and `HealthVfxDirector` all subscribe. Nothing references anything — delete the conductor and every subscriber falls back to its own behaviour.
- **The rule that replaced state floors:** `fear = distanceCurve(proximity) × awarenessMultiplier × closingMultiplier`, held up by a decaying memory of the recent peak. Awareness is a MULTIPLIER, so a far-away enemy cannot manufacture panic — any multiple of near-zero proximity is still near-zero. Floors could, and did: Detected at 30u used to snap the heart to 150 bpm.
- **Distance:** `fearStartDistance` 26u vs a camera showing ~10.7u, so unease starts while he is still off screen. Uses **navigation-path distance** where the navigator has a route (capped at 3.5× the straight line, else it falls back), so a maniac through a wall is not treated as one down an open corridor. Hysteresis of 4u stops the heartbeat flickering at the boundary.
- **The heartbeat is scheduled, not pitched:** `secondsPerBeat = 60/bpm`, with ±2.8% timing and ±3.5% volume wobble. Speeding a heart by pitching the sample reads as a tape running fast.
- **Asymmetric by design:** rises in ~1.4s (0.45s on a spike), holds 3.5s, then decays over 9s. Aftershock is where the dread lives.
- **Visual outputs are published PRE-SCALED** (already through `visualFearEnabled` and the master multiplier), so a visual feature applies them blind and cannot forget to honour the master switch.
- Menu `Setup/45`. Verified by `FearConfigTests` (curve monotonicity, the design BPM/volume targets, mid-range detection, ambience ducking without muting, sting anti-spam).

### Recording (`C#/Recording/`, namespace `TimeKiller.Recording`) — the game records itself
Built so a reviewer with no screen and no ears can still study a session. Three streams per run into `<project>/Recordings/<stamp>/` (gitignored, and outside `Assets/` so Unity never imports thousands of frames):
- **`state.jsonl`** at 4 Hz — fear, stage, bpm, awareness, both distances, HP, positions, duck level.
- **`frames/*.jpg`** at ~1 Hz — what the player actually saw, F1 overlay included, so **every frame carries its own ground truth** and nothing has to be clock-synced.
- **`audio.wav`** — the FINAL mix, captured off the AudioListener with `OnAudioFilterRead`. This is what turns "the heartbeat accelerates" from a claim into a measurement. The audio thread only copies into a locked buffer; all file work is main-thread.
- **F9/F10/F11 mark *boring / unfair / great*.** The only signal here no machine can generate, and the whole reason a human tester beats the bot.
- **Survives a scene reload** via statics + append — proven, not assumed: a forced reload mid-recording continues the same file across the seam (`10.07 → 10.08`). The session clock is `unscaledTime` and **monotonic by construction**, because the analyser sorts on it and a reordered timeline silently misattributes every finding. Note *what* reloads: GameFlow does **not** reload on death (it freezes and waits for **R**) — `BatchRunner` does, between bot runs.
- **The last row says which ending it was.** `"reload"` promises a continuation; `"end"` means the file is complete. They used to share the label `"reload"`, so every finished session looked truncated and four of them were investigated as data loss before the resume was shown to work. `analyze_session.py` now opens on that distinction (`session:unresumed` / `session:truncated`, sev 97).
- `Tools/Playtest/analyze_session.py` ranks findings; `/watch` packages the ritual; `Tools/AudioPipeline/audit_audio.py` audits every asset and guards an approved baseline.

### Health VFX (`C#/HealthVfx/`, namespace `TimeKiller.HealthVfx`)
Diegetic health — no HP bar, the screen is the health bar (design 2026-07-22). Bands on 3 HP: **3 = clean · 2 = subtle red heartbeat vignette · 1 = heavy blood + panicked breathing = "next hit kills"**, plus a splatter flash on every hit.
- **HealthVfxDirector** — subscribes `PlayerHealthChangedEvent`/`PlayerHitEvent`/`PlayerDiedEvent` only (knows nothing about player/maniac; delete the object and the game runs unchanged). One BPM phase clock (74 at 2 HP, 118 at 1 HP) drives every VISUAL in sync: URP Vignette + Chromatic Aberration (|sin|³ systole modulation), dual counter-pulsing blood layers with scale-breath, film grain + desaturation ramps. The audible lub-dub is **not** here — `PlayerHeartbeat` owns it and folds injury into one intensity (see Heartbeat). Hits: splatter flash (scale punch) + Cinemachine impulse shake + pitch-jittered blood-splash SFX; death: impact sting; critical: breathing loop fade.
- **HealthVfxConfig** (SO) — band thresholds, per-band vignette/overlay/chromatic/grain/desat, screen-pulse BPM + pulse depths, hit/death SFX levels, shake/punch, fades. Asset: `C#/HealthVfx/Configs/`. (Heart *volumes* live in `HeartbeatConfig` now.)
- Assets: OpenGameArt CC0 blood overlays reprocessed by `Tools/VfxPipeline/process_blood.py` (radial edge mask, two-tone crimson); heartbeat synthesized by `Tools/VfxPipeline/gen_heartbeat.py` (S1/S2 physiological model, license-free); breathing/splash/impact from the PSX SFX pack.
- Setup: menu `TimeKiller/Setup/22` (also run by Setup/18) — **re-runnable**: every object is found-or-created and re-wired in place, never destroyed and rebuilt, so it cannot discard hand-tuning. Dev cheat: **F7 = take 1 hit** (respects i-frames).
- Camera note: `CameraConfig.lookAheadDistance` set to **0** (user decision 2026-07-22) — player stays dead-center; the look-ahead system remains available via the slider.

### Heartbeat (`C#/Heartbeat/`, namespace `TimeKiller.Heartbeat`) — one clock, one voice
The audible heartbeat has a **single owner**. It used to have two: HidingVfx ran a distance-driven heart inside wardrobes and HealthVfxDirector ran a separate one at low health, each with its own AudioSource and its own phase — so being hurt *inside* a wardrobe played two unsynchronised hearts at once.
- **PlayerHeartbeat** — a `PlayerHeartbeat` child of the Player with its own 2D AudioSource. **The heart answers exactly one question: how close is he?** Distance drives the rate continuously on a curve (`distanceCurve` 2.2 — the panic is in the *change* of rate, which a straight line never delivers); Suspicious and Detected raise **floors** under that, never additions, because two things stacking would run off the top and make the loud end meaningless. Sprinting and injury floors were tried and **removed** (2026-07-28): both made the heart pound with the maniac nowhere near, which is precisely what turns it into background noise — exertion is the lungs' job. Rises in 0.5s, falls in 4.2s, because being safe and *feeling* safe are different things. Silent below `silenceBelow`. Pitch rises to `pitchAtMax` as it races; `irregularity` keeps it off the grid; `hiddenBoost` while hidden. One immediate **lurch** beat fires the instant he detects you. `Soften()` lets the recovery breath through. Exposes `Intensity`/`Bpm`/`BeatThisFrame`/`BeatCount`. Removable. F1 line `Heart`.
- **PlayerBreathing** — the other half of the body, and deliberately **decoupled from fear**: only an **active chase** winds you, over `secondsToWinded`, recovering over the longer `secondsToRecover`. Ordinary running was tried as a trigger and rejected — the player runs almost constantly, which made breathing a permanent bed nobody heard. Holds your breath while hidden and hunted. Exposes `Exertion`/`Holding`/`RecoveryBreathCount`/`RecoveryDueIn`. F1 line `Breath`.
- **The recovery breath waits ~8.5s** (`recoveryDelaySeconds`, user ruling 2026-07-28). It used to fire the instant `Perception.Level` left `Detected`, which was wrong twice over. Relief is not instantaneous — but worse, `Detected` drops *every time line of sight breaks*, which mid-chase happens behind every pillar, so the "I got away" exhale was going off repeatedly **while he was still hunting**. The chase ending now only **arms** the breath; he must stay off you for the whole delay or re-acquiring you cancels it. The `recoveryNeedsExertion` gate is judged **when the chase ends**, not when the breath fires, so the waiting cannot cancel a breath that was earned.
- **Panting is held up through that wait** (`settleDecayScale` 0.35). This is not decoration: measured against the shipped config, decaying at the normal rate leaves exertion at **0.229** after 8.5s versus a `silenceBelow` of 0.22 — a margin of 0.009, i.e. the exhale would land out of dead silence. At 0.35× it lands at **0.730**, on top of audible breathing. Verified alongside the gate: a 2s scare reaches 0.331 and correctly arms nothing; a 5s chase reaches 0.831 and does.
- **HeartbeatConfig / BreathingConfig** (SO) — assets in `C#/Heartbeat/Configs/`. Heart: rate curve + state floors, rise/fall, volume + silence floor + quiet floor, pitch, ducking. Breath: winding/recovery seconds, volumes, pitches, recovery-breath gate + delay + settle decay, and heart-soften.
- **Audio assets** are synthesised in-house (`Assets/Assets/Heartbeat/`) and measured, not eyeballed: the beat must decay inside the fastest beat interval (265ms clip vs a 375ms interval at `nearBpm`), and must carry real energy **above 100Hz** or it is inaudible on laptop speakers regardless of volume — v1 sat 97% below 100Hz and could not be heard at all.
- The other two systems keep only their **visuals**: HealthVfxDirector still runs a screen-pulse clock, HidingVfx still runs the slat overlay. Neither has an AudioSource field any more.
- Setup: menu `TimeKiller/Setup/36`. **`TimeKiller/Setup/37`** is the one-off janitor that removes the now-orphaned `HealthVfx/Heartbeat` and `HidingVfx/HiddenHeartbeat` objects from scenes built before the split — it only deletes a childless object carrying nothing but a Transform + idle AudioSource, and re-running it after a clean run is a no-op.

### Blood (`C#/Blood/`, namespace `TimeKiller.Blood`) — the castle keeps the evidence
Design (2026-07-28): you bleed while wounded and the floor remembers it for the whole run. Built in two passes — **this is pass 1, atmosphere only.** Maniac tracking is approved but deliberately not wired yet, so the look can be judged before the difficulty changes.
- **BloodTrail** (on the Player) — two ways blood is spilled: **the wound** (a splash the moment you are hit, thrown away from the blow using `PlayerHitEvent.SourcePosition`) and **the trail** (a drip every `dripInterval` while at or below `bleedAtHp`, accelerating toward death via `criticalBleedBonus` — bleeding out should feel like it is getting worse, not steady). A **distance gate** (`dripMinDistance`) means standing still cannot stack a puddle on one spot; that also stops a stationary player handing the maniac a beacon once tracking exists. Reads health only off the bus, so it survives the health feature being stripped.
- **BloodSpilledEvent** — the seam. `BloodTrail` publishes, `BloodStainField` draws, neither references the other: delete the field and events fall unheard, delete the trail and the field never fills. Anything else that bleeds later (the maniac, a trap, a broken prop) marks the floor for free by publishing this.
- **BloodStainField** — every stain as **ONE mesh**. A fixed-size ring buffer rebuilds a single dynamic mesh, so cost is one draw call and zero per-spill allocation whether there are 3 stains or 220; when full, the **oldest is overwritten**, so a long run can never degrade into a slideshow. Two load-bearing details: **rotation is quantised to quarter turns** (+ mirror) because arbitrary angles resample the sprite off the pixel grid and reintroduce exactly the mush the droplet art was rewritten to avoid; and **drying** (fresh → darker, browner tint over `dryingSeconds`, so an old trail stops shouting as loud as a fresh one) is refreshed at ~5Hz and *only while something is still wet*, then stops touching the mesh entirely — fading every stain every frame forever is the obvious way to write it and the reason decal systems get blamed for frame drops.
- **BloodConfig** (SO) — capacity, sorting order, size range, drying time + fresh/dried tints, bleed threshold, drip interval/distance/count, critical bonus, and the per-hit splash. Asset: `C#/Blood/Configs/`. Tracking knobs are deliberately **absent until tracking exists** — this project has already paid once for config fields that outlived the code reading them.
- **Sorting order −6**, measured against the scene rather than guessed: floor tilemaps sit at −9…−20 and characters at 0, so −6 puts blood on the floor and under everything that walks on it.
- Setup: menu `TimeKiller/Setup/39` (safe to re-run; found-or-created in place). Removing the feature = delete the `BloodStains` object and the `BloodTrail` component. F1 lines: `Blood` (stain count) and `Bleed` (are you bleeding, and how fast).
- **Pass 2, not built:** the maniac tracking the trail. The seam is already there — `ManiacPerception` consumes `WorldNoiseEvent` and exposes `LastNoiseCause` from a `NoiseCause { Sound, Suspicion }` enum, so tracking is an additive third cause plus a proximity query, with **no hard reference** from Maniac to Blood. It must ship behind a config flag and be A/B'd with the bot playtester: the maniac's difficulty is tuned across five passes, and a homing trail could make the 1-HP state unsurvivable rather than tense.

### Effects (`C#/Effects/`, namespace `TimeKiller.Effects`) — the "Feel-lite" juice system
One juice moment = ONE asset. `EffectPlayer.Play(recipe, worldPos)` fires a full impact package; adding a new effect to the game = creating a recipe asset, zero new code.
- **EffectRecipe** (SO) — **two visual paths, either or both** (2026-07-28): `sheetClip`, a hand-drawn sprite-sheet burst in our locked art style (+scale/material/sorting/randomFlip/randomRotation), and `particlePrefab`, a ParticleSystem (+scale/lifetime). Plus random SFX clips (+volume/pitch jitter) and Cinemachine shake (strength/duration). **Which to use:** drawn sheets for anything with a readable shape that the player looks at (impacts, sparks, a clock waking up); particles for continuous, never-repeating, many-tiny-elements work (embers, dust, fog) where a drawn loop would read as a repeating tile. `sheetMaterial` left empty = the default **lit** sprite material; assign an **unlit** one for anything that must glow — a lit VFX sprite is invisible in exactly the dark corners where it matters.
- **EffectPlayer** (static) — lazily builds its own runtime rig (audio source + impulse source), then spawns whichever visuals the recipe declares. No scene setup needed. A one-shot sheet is destroyed exactly when its last frame has played (`frames ÷ fps`), so a mistuned lifetime can never truncate it; only a *looping* sheet falls back to `particleLifetime`. Nothing is pooled — these live well under a second and a pool would cost more than the allocation it saves.
- **VFX sheet pipeline** — PixelLab strips land in `Assets/Resources/Assets/Effects/Vfx/`, `Tools/VfxPipeline/build_vfx_strip.py` stitches frames into one row of square cells, and **Setup/38** slices them into `SpriteAnimationClip`s in `C#/Effects/Configs/Clips/`. Two rules there: sheets are **centre-pivoted** (a character pivots at the feet so it stands on the floor; a burst must sit on the point it was played at) and imported at **32 px/unit**, the world's scale contract. Re-running Setup/38 refreshes frames but **preserves** any `framesPerSecond`/`loop` you tuned by eye — same principle as the scene rule.
- **PlayerHitEffects** — binds `PlayerHitEvent` → PlayerHit recipe (world blood burst + splash SFX + shake) and `PlayerDiedEvent` → PlayerDeath recipe (bigger burst + impact sting + heavy shake). Impact juice lives HERE; HealthVfxDirector is screen-state only (bands/heartbeat/breathing/flash).
- **BloodBurst particle prefab** (rebuilt 2026-07-28, the "looks cheap" pass): built by Setup/23 from droplets **drawn on-palette** by `Tools/VfxPipeline/draw_droplets.py`. The previous droplets were fragments cropped out of the CC0 splats and *every one was clipped by the frame edge* — a ParticleSystem draws each sprite centred on its particle, so a droplet whose art sat in a corner rendered visibly offset with a hard straight cut. They were also flat `(166,15,11)` red with no dark rim, while the project's blood palette (from `process_blood.py`) is rim `(38,2,2)` → core `(150,12,8)`; the rim is what makes blood read as wet rather than as a red dot. The replacements are **pixel-art spatter**, six variants atlased 3×2 for **Texture Sheet Animation random-frame** variety so no two droplets in a burst are the same stamp.
  - **The style rules, and why** (rewritten after the first drawn pass was rejected as "looks cheap, not horror"). Measured against the real game art (`wardrobeA_closed`, `Survivor_Idle_Down`), the world is **hard-edged pixel art, median value 52, median saturation 0.07**. The first drawn droplets were supersampled-then-downsampled metaballs at **saturation 0.93, value up to 165, perfect ellipses with a radial specular** — mismatched on *every* axis, so they read as airbrushed candy-red gumballs pasted onto muted pixel art. Three rules came out of that, and breaking any one puts the gumballs back:
    1. **No antialiasing.** Draw at final resolution with boolean coverage — alpha is only ever 0 or 255. Hard edges are most of what makes the world read as pixel art.
    2. **Quantised shading.** Exactly four palette steps chosen by depth-from-edge; never a continuous ramp, and *never* a radial specular — a smooth radial ramp with a highlight is precisely what makes a shape read as a 3D sphere.
    3. **Irregular silhouette.** Harmonic noise on the polar radius, plus tendrils flung outward and detached satellite specks. Real spatter is torn; an ellipse is a berry.
  - **Authoring resolution is 32px cells**, because the world is 32 px/unit — a 32px cell at particle size 1.0 displays at exactly 1:1, and the atlas imports with **Point** filtering to match everything else. The earlier 64px cells were downscaled on screen, reintroducing blur no matter how crisp the source. Visual size variety comes from how much *ink* each tile holds (~8–26px across), **not** from scaling particles: scaling pixel art is what makes it mushy.
  - Nothing may touch the cell edge — it bleeds into the neighbouring atlas tile and shows in game as a stray sliver. The generator clamps tendril length and speck distance structurally rather than trusting the radius numbers, so retuning a radius can't silently reintroduce it.
  - Tuning that matters: fast out + hard velocity damping + heavy gravity so blood is *thrown then falls*; alpha holds and drops late, because blood doesn't fade as it flies; **world** simulation space so spatter stays put when the victim moves. `radiusThickness 0.55` + `randomDirectionAmount 0.62` + a wide `startSpeed` (1.4–10) because a narrow speed range sends every droplet out in lockstep and the burst reads as an expanding **ring** sweeping over the player. **Count is the knob that decides wound vs paint bomb** — at 46 droplets of near-1:1 spatter the burst buried the player completely; 24 droplets + 5 gouts reads as a hit while leaving you visible, which is non-negotiable in a game about running and hiding.
  - **Splat child** — the part that actually reads. Flying droplets are thin and brief; what tells you *you were hit* is blood that stays. Eight fat gouts that barely travel, settle fast, spread slightly as they land (a splat widens, it doesn't shrink) and linger ~3s. Capped at **0.72u** on purpose: the survivor is 0.9u tall, so a bigger gout is a single blob larger than the character, and you must always be able to see yourself in a game about running and hiding.
  - ⚠️ `TextureSheetAnimation.startFrame` is **normalised 0–1** in Unity 6 and silently clamps — the ScriptReference example showing a 0–7 slider for an 8-tile sheet is from an older version. `0 → 0.9999` spans the whole sheet.
- **VfxVisibilityProbe** (`TimeKiller/Verify/VFX Visibility`) — renders an effect in the OPEN scene, at the real camera's ortho size, at the player, and reports what share of the screen it actually covers over time (diffed against a clean plate, so it counts what the effect *adds*). Read-only; renders offscreen, dirties nothing.
  - **Why it exists.** The blood burst was tuned against an isolated neutral backdrop and deliberately tinted *down* to match the palette. In the real castle — floor luminance **10/255** — that put it at **0.26% peak screen coverage, gone inside 0.75s**: it looked fine in isolation and was invisible in play. Visibility is a property of the effect AND the scene behind it, so it has to be measured there. The pass that followed: 0.26% → 0.75% (brighter/bigger) → 0.96% (+ splat child) → **1.52%, still 1.1% at t=1.1s** (droplets redrawn to fill more of their quad — ink was only covering ~27% of the particle's area, so particle *size* wasn't turning into visible blood). Rule of thumb from that pass: under ~0.5% peak on a dark floor will be missed entirely; ~1.2%+ reads.
- **CFXR is no longer preferred** (2026-07-28). Setup/23 used to do `cfxrBlood != null ? cfxrBlood : ourPrefab`, which silently replaced the purpose-built BloodBurst with "Cartoon FX" prefabs — bright, saturated, round, and (measured by deterministic `Simulate()` renders) sparse and gone by t=0.32s. CFXR is still in the project and can be dragged into any recipe by hand; it just no longer overrides our own art. `PlayerDeathSoul` still uses `CFXR2 Souls Escape` deliberately.
- Setup: menu `TimeKiller/Setup/23` (recipes + BloodBurst, also run by Setup/18) and `TimeKiller/Setup/38` (hand-drawn VFX sheets → clips).
- **ClockEffects** (2026-08-04) — binds `ClockHitEvent` → `ClockHit` (the earned press) and `ClockFixedEvent` → `ClockFixed` (the clock wakes), the same binder shape as `PlayerHitEffects`. **No shake on the hit**: a correct press is a reward, and shaking the camera on every one would punish success *and* fight the skill-check bar the player is reading. Both sheets use the **unlit** material — a repair happens standing still in a dark corridor by definition, which is exactly where a lit VFX sprite disappears. Counts play through `DebugOverlay` (`ClockVfx`) so "did it fire?" is a number, not a squint. Setup: menu `TimeKiller/Setup/50`, which slices its own strips via `VfxSheetSetup.BuildClip` rather than making you run Setup/38 first.
- **`clean_burst.py`** (`Tools/VfxPipeline/`) — keys a generated light burst so its dark pixels stop being drawn: *for a light effect, alpha follows luminance*, because anything dark inside a glow is the generator's background, not art. `--fade` adds the hold-then-drop envelope for a strip that would otherwise still be at half strength on its final frame — `EffectPlayer` destroys a one-shot exactly when the last frame plays, so such a burst does not end, it vanishes.
- **ManiacThreatEffects** (2026-08-27) — binds `ManiacSpottedPlayerEvent` → `ManiacSpotted` and `ManiacAttackEvent` → `ManiacSwing`, closing the gap the coverage note below named as the biggest one. Two departures from the other binders, both deliberate: it **self-installs** from Resources rather than being a scene object, because Catacombs never received the Setup pass that placed `ClockEffects` and a scene-object binder is therefore silently absent from half the game's levels; and it carries an **anti-strobe cooldown** (`spottedCooldown` 4s, matching the music sting's since 2026-07-23), because `ManiacSpottedPlayerEvent` fires on every LOS *re-acquire* and mid-chase that happens behind every pillar. The F1 line `ThreatVfx` prints played/heard, and the gap between them *is* the cooldown working — measured: 3 published in one frame → **1 played**. Recipes ship **empty**, so it is wired, counted and silent until the art exists. Setup: `TimeKiller/Setup/52`, which never overwrites a recipe.
- **Coverage, after this pass**: 17 gameplay moments publish on the bus; `PlayerHitEvent`, `PlayerDiedEvent`, `ClockHitEvent` and `ClockFixedEvent` have VFX. Still visually silent: `AllClocksFixedEvent`, `GameWonEvent`, and the maniac's threat beats `ManiacSpottedPlayerEvent` and `ManiacAttackEvent` (the last two were audio-only — voice and sting — which is the biggest remaining gap, since being seen is the emotional peak of a hide-and-run game). **Update 2026-08-27:** the two threat beats now have a binder, recipes and counters (`ManiacThreatEffects`), but their sheets are empty, so in play they are still **visually** silent until the art lands. With no binder at all: `AllClocksFixedEvent` and `GameWonEvent`.

### Audio mix (`C#/Audio/AudioMix.cs` + `AudioMixConfig`) — priority, measured
**The problem, measured before building anything:** during a chase nine sources wanted the same instant and their linear amplitudes summed to **6.72× full scale** (Unity hard-clips above 1.0). Three of them — heartbeat 1.00, maniac breath 0.85, growl 0.90 — stacked to **2.75 below ~300Hz**, masking each other into mud. Volumes lived in **eight separate config assets**, so the balance could not be seen, let alone set. `AudioDucking` governed exactly one relationship (heart → score) and **6 of ~12 sources ignored it**.
- **`AudioMix`** returns a **multiplier**, never an absolute level, so every system keeps computing its own volume and the tuning already done by ear survives (`chaseVolume` 0.42, `stingVolume` 0.70 were hand-set and are kept). No config → every call returns 1.0 and the game sounds exactly as before. `AudioDucking` stays; this is additive.
- **Tiers, not a mixer.** Unity exposes no public API to create AudioMixer groups or effects from script, so a mixer asset would have to be hand-built in the editor. A code bus keeps it scriptable and measurable, which is what let the numbers below exist. Tier 0 Sting → 1 PlayerVoice/ManiacVocal → 2 ManiacBreath/Heartbeat → 3 ManiacFootsteps/PlayerBreath/Effects → 4 PlayerFootsteps → 5 Music/Ambience. A channel ducks **only for strictly lower tiers** — equal tiers never duck each other, or the mix would flip-flop on whichever arrived last.
- **Duck duration comes from the clip**, via `Announce(channel, clip.length)` called *before* `PlayOneShot` — a fixed window is either too short for a death cry or too long for a footstep, and announcing after the fact ducks for a sound already buried.
- **PlayerFootsteps has `duckDepth` 1.0** — trimmed by the mix, never ducked by it. Muting the feedback you steer by reads as a bug, not as tension (the same reasoning `AudioDucking` documents).
- **The low-band rule.** The heartbeat is multiplied by `heartUnderManiacBreath` (0.4) as his breath gets loud, because they cannot both own sub-300Hz. Information beats emotion: his breath tells you *where he is*, which you can act on, and the heart's **rate** still carries proximity at any volume — so ducking its level costs nothing. ManiacVoice pushes its *intended* loudness (pre-mix) to avoid a feedback loop.
- **Self-loading.** `Resources.Load("C#/Audio/Configs/AudioMixConfig")` in `RuntimeInitializeOnLoadMethod` — the whole `Assets/Resources/` tree is a Resources root, so the mix applies in Castle wing, Catacombs and any future scene with no component to forget. Deleting the asset is the uninstall. Statics are reset on load for the same domain-reload reason `AudioDucking` documents.
- **Result (measured, same worst case):** peak-sum **6.72 → 3.01**, power-sum (the honest figure — uncorrelated sources add as power) **2.21 → 1.20**, low band **2.75 → 1.28 (53% quieter)**. Typical states: calm exploring power-sum 0.61, he's-close-and-hunting 1.01. Runtime-verified: a sting ducks music 0.680→0.516 and falling while footsteps hold flat at 0.723, and heart gain falls 0.519→0.173 as his breath rises.
- Setup: menu `TimeKiller/Setup/40`, which **never overwrites an existing asset** — this config is tuned by ear in Play Mode and a setup script that reset the faders would destroy the work it exists to hold. F1 line `Mix`.
- **Generated voice clips are loudness-normalised** by `Tools/AudioPipeline/process_voice.py` to a common **-12 dBFS RMS** with a tanh soft limiter. Peak-normalising was tried first and rejected by measurement: it left the first batch at -13.7 to -15.7 dB RMS (~7 dB under the heartbeat, i.e. buried) because a clip with one sharp transient peaks the same as a sustained one. Loudness-matched, the batch lands within **0.2 dB** of itself — which is what lets the mix config own the balance instead of fighting the source material.

### Voices (2026-07-28) — the maniac's presence and the player's body
**NON-VERBAL ONLY** (user ruling). Nobody in this game speaks. Breath, throat and boots — nothing that needs a language, dates itself, or explains him. Setup: menu `TimeKiller/Setup/39`, which **fills empty slots only** so a re-run can never delete the generated voice set.

- **ManiacVoice** (`C#/Maniac/`) — until this existed there was **not one AudioSource anywhere under `C#/Maniac/`**: he was completely silent. That was a gameplay hole, not an aesthetic one — the first information the game ever gave you about him was *seeing* him, which is exactly why hiding measured as inert in the bot playtests (81.8% vs 81.9% death, `nearMissHidden` 0). The breathing bed is the counterplay: a 3D loop whose volume reads as distance, so a listening player can place him through stone and hide **before** he rounds the corner. Presentation only, like `ManiacAnimationDriver` — it reads his components and never drives them.
- **Deliberately not occluded by walls.** Real stone would muffle him, but the muffling is precisely the information the player needs, and a horror game that hides its tells from an attentive player is only unfair.
- ⚠️ **Unity's built-in 3D rolloff is unusable in this project.** The `AudioListener` rides the Main Camera and `CameraFollow` preserves the camera's authored Z (**measured: −10**), so Unity measures the distance to him as `sqrt(d² + 100)` — standing directly on top of him reads as **10.0u**, leaving a 1-unit usable band inside an 11u `hearingRadius`. All three sources therefore use a **flat custom rolloff curve** (Unity does the panning) and `ManiacVoice` applies its own **2D** attenuation, linear between `fullVolumeRadius` and `hearingRadius`. Linear over inverse-square on purpose: inverse-square puts nearly all its change in the first metre and leaves the rest an undifferentiated whisper, which destroys the one thing the system exists to convey. Measured curve: 1.5u→1.00, 3u→0.84, 5u→0.63, 7u→0.42, 9u→0.21, 11u→0.00.
- **Breath intensity is state, not just distance** — volume and pitch follow `Perception.Level` (Unaware 0.35 / Suspicious 0.55 / Detected 0.85), blended over `breathBlendSeconds` so it reads as a mood changing rather than a switch flipping. One clip for all three: swapping clips would put an audible seam on the exact moment he notices you.
- **Vocalizations**: `spottedGrowls` on `ManiacSpottedPlayerEvent`, `lostYouGrowls` on the `Chase→Search` transition (the mirror of the player's recovery breath — their relief and his frustration are the same moment from the two ends of it), `attackRoars` on `ManiacAttackEvent`, rare `idleMutters` only while Unaware. All cooldown-gated. An empty pool is silent by design.
- **Footsteps run off distance travelled** (`strideMeters`), not animation event frames — his clips are not guaranteed to carry foot-contact frames the way the player's run clips do, and distance stays correct at every speed including the slow investigate walk.
- **PlayerVoice** (`C#/Player/`) — pain, panic, effort, and the last cry, all off the bus. Pain is driven by `PlayerHealthChangedEvent` going **down**, *not* by `PlayerHitEvent`: the latter is published by the attacker and fires even inside the invulnerability window where it does nothing (`PlayerHealth.cs:72` returns early), so grunting there would cry out for damage never taken. A separate `painGruntsCritical` pool below `criticalAtOrBelow` — with no health bar on screen (health is diegetic by design) **the grunt is the health readout**. Death cry on `PlayerDiedEvent` suppresses the grunt for the killing blow; gasp on being spotted, deliberately under the music's jumpscare sting; quiet `repairEfforts` while `ClockRepair.Repairing`. Exposes `PainCount`/`GaspCount`/`DeathCount`. F1 line `Voice`.
- ⚠️ **`seed_audio` defaults to a FEMALE voice when no `voice_id` is passed.** The first maniac set was generated without one, so `pitch_rate -12` produced a pitched-down woman — rejected by ear 2026-07-28 ("normal girl's voice going haaa"). His 13 vocals are now generated with **`voice_id 7e63ac18` (Roman, male, user's pick)** and then **monsterised**. Always pass a voice.
- **Monsterising** (`Tools/AudioPipeline/monsterize.py`) is what makes a throat inhuman, and a deep preset alone does not do it — a pitched-down man still reads as a man. Three effects, none available as a TTS parameter: a **formant-shifting** pitch drop via resampling (−3.9 semitones; moves the skull and throat resonances down *with* the pitch, so it reads as a bigger body rather than a slowed tape), a **sub-octave** layer at 30% for weight, and a **detuned double** at 40% — two copies beating against each other, which is the strongest cue of all, because a real throat cannot produce two pitches at once and the ear refuses to hear it as one person. Then tanh saturation for grit and a re-normalise to −12 dBFS. Player voices are deliberately NOT monsterised — they were approved as-is.
- **The voice set is generated and wired: 27 clips** in `Assets/Assets/Voices/` — maniac spotted×3 / lost×3 / attack×3 / mutter×4, player pain×3 / critical×3 / death×2 / gasp×3 / repair×3. Made with Higgsfield `seed_audio` (~5.4 credits; the fal.ai backend Unity ships with is unconfigured and was never needed). Maniac at `pitch_rate -12`, player at −4..+3 so the two are unmistakably different throats. **Raw output spanned −12.4 to −52.2 dB RMS** — a 40 dB spread that would have left half the set inaudible beside the other half; `process_voice.py` brings 24 of 27 within 1 dB of −12. `player_paincrit_3` is the outlier at −16.0 dB (the limiter bit hardest there) and is the one clip worth re-rolling if it sounds weak.
- **Assets**: `demon breathing.wav` (PSX pack) is a **stand-in** breath loop — it was authored as a one-shot, so its loop point is untested. Footsteps are eight single steps cut from `tunnel steps.wav` by `Tools/AudioPipeline/slice_footsteps.py`; every "steps" file in the pack is a walking *sequence* (tunnel 8.1s, mud 31.6s) and this system triggers one clip per stride. The slicer's first pass silently merged steps — a share-of-peak threshold tuned for the loud steps dropped the quiet ones (amplitudes range 4640–18337), leaving 0.96s and 1.46s gaps against a true stride of ~0.48s. Fixed with an 80th-percentile threshold and a 350ms refractory: **17 onsets, median gap 0.486s, range 0.451–0.527s, zero missed**. ⚠️ **Growls, roars, mutters and every player line have no source in any owned pack and remain EMPTY** — they need the generated voice set.

### Objectives (`C#/Objectives/`, namespace `TimeKiller.Objectives`) — the win condition
The core loop (design 2026-07-24, DbD-inspired): **fix 3 clocks → the exit gate unlocks → escape**. Removable — delete the `Clocks` object and the game still runs.
- **ClockObjective** — one clock: broken/fixed sprite swap, green Light2D that lights when repaired, repair progress, and a **static registry + `AnyFixed` event** so spawn order never matters.
  - **The light RISES** (2026-08-04, `lightRiseSeconds` 0.45). It used to snap: sprite swap and full-strength light in the same frame, which is why the biggest progress beat in the game read as a state change rather than an achievement. Ease-out, because a linear ramp reads as a dimmer being turned by hand. The target intensity is captured **in `Awake`, before anything animates it** — sampling it at the moment of the rise would latch whatever an interrupted rise had reached, and the clock would come back dimmer after every scene reload. `0` restores the old snap exactly.
  - **`EffectPoint`** — where an effect plays on this clock. The sprite pivots at its **base** (0.5, 0.06) so the clock stands on the floor, which puts `transform.position` a **measured 1.03u below the clock's middle**; a burst played there goes off at its feet. Derived from renderer bounds rather than a hand-placed anchor child, so re-drawing the clock art cannot leave the effect aimed at the wrong spot.
- **ClockRepair** (on the Player) — the mini-game: **E** to start, then a marker sweeps a bar and **SPACE** inside the green zone adds progress; a miss costs a little and emits a quiet noise (via `PlayerFootstepEvent`) he may hear. Progress persists; the maniac inside `interruptRange` kicks you out. Reads `IInputSource.SkillCheckPressed` — the same seam co-op/AI input uses.
- **ClockRepair.RepairState** — starting a repair turns the player to face the clock and **locks them in place** (DbD-style commitment, user ruling 2026-07-25). The state has no transitions of its own: movement input is simply ignored, and that *is* the lock. Every exit (E again, the maniac, the clock finishing, drifting out of range) is decided in `ClockRepair.Repair` → `Stop`. Its **class name is the animation key** — `PlayerAnimationDriver` matches the string `"RepairState"` and plays `PlayerAnimationSet.GetRepair`, so renaming the class silently falls back to the idle pose. The repair clips carry **no `eventFrames`**, so standing at a clock broadcasts no phantom footsteps.
- **ObjectiveManager** — tallies fixed vs total, fires `AllClocksFixedEvent` on the last one, publishes `RunEndedEvent` on the win, and lends its tally to the end screen via `GameFlow.ProvideSummary`. `ClockFixedEvent` now carries **`Position`** as well as the tally: a count says a clock was fixed but not *which one*, and an effect needs somewhere to happen.
- **`ClockHitEvent`** (2026-08-04) — the mirror of `ClockMissEvent`, and the seam the repair loop was missing. A fumble had a ring and a noise from 2026-08-02; a **correct** press called `AddProgress` and nothing else, so the one beat the mini-game rewards you for was the only silent one in it. Deliberately **not** published on the press that finishes a clock — that press belongs to `ClockFixedEvent`, and firing both would stack a small burst under a big one on the same frame.
- **ExitDoor** — locked/open sprite states sharing a pixel-identical stone arch, a blocking collider while locked, a 3D **wind beacon** loop you can navigate back to once it's open, a local creak, and a map-wide `WorldNoiseEvent` on opening so the maniac learns where the exit is. Swaps to an unlit material when open so the night beyond self-glows.
- **ObjectiveHUD** — IMGUI counter + skill-check bar; hides itself once `GameFlow.Phase != Playing` (the end screen owns the screen from then on).
- **ClockConfig** (SO) — repair tunables. Asset: `C#/Objectives/Configs/`.
- **PROTECTED PLACEMENT** — same class as HidingSpots and Furniture: Setup/28 refuses to rebuild if a `Clocks` object exists. Hand-placed spots are recorded as the seed constants in `ClocksSetup.cs`.
- **Map gotcha worth remembering:** doors belong on **north** walls — south walls render an Overhead band that draws over anything standing there.
- Art: clock (PixelLab, from the user's reference) in `Assets/Resources/Assets/Objectives/Clock/`; gate in `.../Door/`. Setup: menu `TimeKiller/Setup/28`.

### UI text & fonts (`Assets/Resources/Assets/UI/`, setup in `C#/Core/Editor/`)
Two hand-authored **pixel fonts**, so they carry a constraint ordinary fonts do not.
- **The grid rule.** `TimeKiller_Display` is drawn 32 units-per-pixel against a 1024 em → native em **32px**, crisp only at **32/64/96**. `TimeKiller_Body` is drawn at 64 → native em **16px**, crisp at **16/32/48**. Any other size lands a 2px stem across a fraction of a screen pixel and the glyph goes soft. `Setup/48` enforces this over every scene and is idempotent; `ObjectiveHudSetup`, `RunEndStyleSetup` and `PauseMenuSetup` each carry the rule as a comment at the call site.
- **The same rule applies at bake time, and that is the one nobody caught.** The atlases shipped at `samplingPointSize` 90 — fractional against both grids (2.8125× and 5.625×) — so the blur was baked into the texture where no runtime setting could reach it. Diagnosed from the glyph metrics: 54.1% / 50.0% of them were non-integer. Rebaked on-grid at **96 / 64** by `Setup/47`; both now read **0.0%**.
- **`Setup/47` rebakes IN PLACE.** The material and atlas are sub-assets the scenes reference by fileID, so it copies glyph data onto the existing objects and re-points the references, rather than creating new assets. Creating new ones silently breaks every `TMP_Text` in the project.
- **Held constant deliberately:** padding 9 → `gradientScale` 10, which keeps the tuned outline (0.18, black) at its exact weight — that outline is what carries legibility over the dark floor. Atlas filter stays **Bilinear**: an SDF is sampled and thresholded, so point filtering would stair-step the distance values.
- **Population mode is Static** (`Setup/46`) so playing the game stops rewriting the font assets — that churn was measured at 826 deleted lines in one session's diff.
- **Shader is the desktop `TextMeshPro/Distance Field`**, not the Mobile variant: PC-only game, and only the desktop one exposes `_Sharpness` (currently **0.4**).
- **Canvas scale match:** 0.5 on `RunEndCanvas`, `MenuCanvas` and `PauseCanvas` so the UI survives non-16:9 monitors. **`ObjectiveHudCanvas` is deliberately 1** — it hugs top and bottom. `BloodCanvas` / `SlatsCanvas` are full-screen effect overlays with no text; their 800×600 reference is harmless.
- **`SetupGuard` (`C#/Core/Editor/`) — call it first in every `TimeKiller/Setup` item.** `if (SetupGuard.Blocked("43 - Build Pause Menu")) return;` refuses in play mode and mid-compile, and logs why. Editor scripts do not merely fail in play mode, they **half-run**: Setup/43 built and rewired its whole rig before throwing at `MarkSceneDirty`, and play mode then discarded the lot. **As of 2026-08-03 only 9 of 65 menu scripts guard themselves** — 43/47/48 do; the rest is an open sweep.
- **9-slice centres are not necessarily empty.** `EndFrame.png`'s centre is 79% transparent, not 100%: rows y 56..72 are solid and stretch into the ledge under the pause buttons. Anything meant to fill a frame's middle must be a **sibling ordered ahead of the frame**, never a child of it, or it draws over the art.
- **Two rect traps, both caught in the pause menu (2026-08-03).** `PauseMenuSetup.Anchor` forces **pivot 0.5**, so anything anchored to an edge must be offset by *half its own width/height* to line up — a bare padding value silently pushes it outside the panel. And the frame's usable area is the panel rect **minus the 9-slice border**: read it off the sprite (`sprite.border / ((spritePPU / canvas.referencePixelsPerUnit) * image.pixelsPerUnitMultiplier)`), not off the art README. For EndFrame at 760×620 that is x −320..320, y −262..252. Both setup scripts now carry the full layout budget as a comment so the arithmetic is checkable without re-deriving it.
- **Catacombs never went through the TMP migration** (`Setup/44` only ran on CastleWing), so its UI is still legacy `UnityEngine.UI.Text` while `RunEndScreen`'s fields are `TMP_Text`. The references are dangling the moment the scene loads, and simply opening and **saving** the scene writes those nulls to disk. `Setup/48` therefore skips Catacombs by name. Migrate it before touching its canvases.
- **Known gap:** the TTFs contain 76 glyphs. `# $ % & * < = > @ [ \ ] ^ _ \` { | } ~` and all curly quotes/dashes/ellipsis **do not exist in the font files** and cannot be baked — they must be drawn as ASCII-art skeletons in `Tools/UIArt/add_glyphs.py`, in both weights. Nothing uses them today.

- **Bot playtester** (`C#/Testing/`, 2026-07-25) — a simulated *player*, not an oracle, so balance questions get answered by running the level 200 times instead of arguing. `BotPilot` is a state machine (Explore / Repair / Flee / Hide / Escape) pressing only the four inputs a human has, through `ScriptedInputSource`; `BotPath` follows A* waypoints over the maniac's own `WalkabilityGrid` (straight-line steering grinds walls). Two rules keep the instrument honest: **`BotMemory`** — clocks, wardrobes and the gate are unknown until the bot has line of sight to them from inside `sightRange`, so it must explore and *find* them like a first-time player; and **`BotProfileConfig`** — reaction lag, un-compensatable reaction jitter and perception noise on the marker read, because a bot reading `ClockRepair.Marker` directly hits 100% of skill checks forever and reports the game is easy. Profiles ship in two families never mixed in one report: honest (`novice/average/expert`) and `oracle_*` (`knowsEverything` — the "already memorised the castle" upper bound). `BatchRunner` (DontDestroyOnLoad, all waits on realtime because `GameFlow` sets `timeScale = 0` on run end, `Random.InitState` per run so failures replay) writes one JSON row per run to `Tools/Playtest/results/*.jsonl`; `Tools/Playtest/analyze.py` aggregates. Accelerated runs are only trusted against a matched-seed 1x control block — a win rate that moves with `Time.timeScale` is measuring the accelerator. Menu: `TimeKiller/Setup/33`. **Nothing in gameplay references any of it** — deleting `C#/Testing/` leaves the game intact.
- **Wall-stuck instrumentation + A/B arms** (2026-07-25) — `BotPath` counts stuck events, give-ups, wedged seconds and **travel seconds** (the denominator: the arm that wedges less also lives longer, so raw counts penalise the better one). `BotPilot.RetireNav` folds the counters forward across the mid-run grid rebuild that fires when the gate opens. `BatchRunner.Request.BodyRadii` runs **every seed once per pathfinding** — `0` is the old hairline string-pull `GridPathfinder` documents, `BotPilot.DefaultBodyRadius` the real player capsule — old arm first, so a killed batch still leaves the irreproducible baseline on disk. This exists because the counters are new: there is no instrumented history, so the baseline is measured alongside or not at all. `analyze.py` keys every cell on `bodyRadius` too — merging arms would average a baseline into the thing it is the baseline for.
- **Tension trace + derived thresholds** (2026-07-25) — win rate cannot tell a horror game from a chore, so `TestTelemetry` also samples the *shape* of a run (near misses, chase episodes, dead air, a unitless 12-slice threat curve) in `FixedUpdate`, never `Update`, so a 6x batch yields the same samples per game-second. Its three sensory thresholds are **derived from `ManiacConfig` at run start, not typed in**: `FeltRadius = max(sightRange, hearingRadius)`, `NearMissRadius = sightRange × 0.57`, `awareThreshold = suspicionThreshold`. Hard-coding them had put `FeltRadius` three units *beyond* his maximum sensory reach (a 9–12 limbo band that was neither felt nor dead air) and `awareThreshold` *below* the game's own `suspicionThreshold` (dread counted a band where he does nothing). Each row records the thresholds it was measured with, because deriving them means retuning the maniac now silently moves every tension number; `analyze.py` refuses to average two threshold sets. Suspicion time is accumulated **inside `ManiacPerception`** per frame rather than sampled — at `awarenessFillRate` 2.6 the band is often shorter than one 4 Hz sample — and split into `StalkSeconds` (still sensing: answers to level design) and `FadeSeconds` (forgetting tail: capped at `(1 − suspicionThreshold) / awarenessDrainRate`, so it is a tuning readout and never a verdict). `ManiacHeardNoiseEvent.Cause` splits audible-player from sight-meter-flicker, which shared one counter.
- **AnimationProbe** (`C#/Testing/AnimationProbe.cs`, menu `TimeKiller/Verify/Probe Player Animations`, 2026-07-25) — play-mode assertions for things a screenshot cannot show: that each of the 8 input octants selects the matching facing *and* the matching clip asset (16 combinations, walk and run), that foot-contact events fire on the frames the art actually plants a foot on and at what real rate, and that a clock repair holds the player still in the work pose and releases on E. Possesses the player through `SetInputSource`, restores the previous source, and deletes itself; writes to **`Temp/animation_probe.txt`** as well as the console, because leaving play mode reloads the domain. Two traps it is built around, both of which bit during development: entering play mode drops any `playModeStateChanged` subscription made beforehand (the request is handed over in `SessionState` and picked up by a `RuntimeInitializeOnLoadMethod` in the fresh domain), and its `[DefaultExecutionOrder(-200)]` is load-bearing — a key pulse that spans two frames is read twice by `ClockRepair`, whose second read means "walk away" and cancels the repair it just started.
- Editor prefs set for headless play: InteractionMode = NoThrottling, PlayerSettings.runInBackground — play mode must keep ticking while Claude works from the terminal.

### Catacombs level (second map, data-driven placement)

`CastleWing.ldtk` holds **two** levels: `CastleWing` and `Catacombs`. The catacombs use their own tileset (`Catacombs`, from `Outsource/RogueFantasyCatacombs/mainlevbuild.png`) via `overrideTilesetUid` on each tile layer, so both levels share one LDtk project, one importer configuration and one set of sorting orders.

Authoring is offline and re-runnable:

```
python Tools/MapPipeline/mapv3_catacombs.py   # regenerate the level + room data
python Tools/MapPipeline/validate_v2.py       # gaps / collision-on-floor, both levels
python Tools/MapPipeline/render_catacombs.py  # composite PNG preview + schematic
```

The generator writes three things and refuses to write any of them if BFS from the player spawn cannot reach every floor cell:
- the `Catacombs` level in `CastleWing.ldtk`;
- `Assets/Resources/Assets/Maps/CastleWing/Catacombs.ldtkt` — LDtkToUnity resolves tilesets through these exported files, and a tileset without one fails to import;
- `Assets/Resources/Assets/Maps/CatacombsRooms.json` — **world-space** room rects and the full walkable-cell set.

**Layer contract (do not break):** the `Floor` layer contains ONLY walkable cells. `validate_v2.py`, the gap audit and this document all treat Floor-layer tiles as the definition of walkable ground. The background rock mass therefore lives on `Rug` (sorts -15: above Floor -20, below WallFace -10, and it never overlaps cobble).

**Scene:** `Setup/30` builds `Catacombs.unity`, unpacking the imported prefab and deleting the CastleWing level so this scene holds the catacombs only. Because it is unpacked, **a reimport does not update the scene — re-run Setup/30 after editing the map.** The Floor tilemap's min cell is pinned to world (0,0); `CatacombsRooms.json` exports against exactly that anchor.

**Gameplay placement:** `Setup/31` calls the existing setup scripts (28 clocks, 25 hiding, 20 maniac, 29 run flow) and then relocates what they created onto positions derived from the room data. The castle's hand-tuned coordinates are never touched. `CatacombsRooms.Anchor()` returns a floor cell with 3 cells of solid rock behind it and clear floor on both flanks, trying north → east → west, never south (south walls render an Overhead band that draws over anything standing there). A shared 3×3 reservation set stops two props claiming the same wall.

**Camera bounds:** the generator emits ONE map-wide `CameraZone` (carved area + 2 cells), not per-room zones. `CinemachineConfiner2D` fits the whole **viewport** inside the bounding shape, so any zone smaller than the viewport (~16×7 world units) makes the confiner park the camera on some other region and the player goes off-screen. If per-room "camera rooms" are ever wanted, every zone must be inflated well beyond the largest supported viewport — sizing a zone to its room is the bug.

**Verification:** `Setup/32` audits the open scene. Note that the Collision layer's `CompositeCollider2D` uses `geometryType = Outlines`, i.e. EDGE colliders with no fill — asking "is this rock cell solid?" with a point query always returns nothing, and is the wrong question. The audit instead replicates `WalkabilityGrid` (0.5 spacing, integer-aligned nodes, 0.9 clearance, blocked = non-trigger hit on a null/Static body), floods from the spawn, and asserts the reachable set is exactly the walkable region: no leak out, nothing unreachable. It runs map integrity with props ignored (a solid clock legitimately makes its own cell unwalkable) and then separately checks no room is walled off by props.


### Tests (`C#/Testing/Editor/`, namespace `TimeKiller.Tests`)
EditMode tests via Unity Test Framework. No asmdef — they live in the predefined
editor assembly, which already references NUnit, so they are discovered with zero
setup. `Window > General > Test Runner > EditMode`. 28 tests, 0.70s.

**The rule that makes them trustworthy: only pure functions.** No scene, no
frames, no physics, no lighting, no MCP round-trip — so the failure modes that
plagued the play-mode probe (a teleport read as "running" and applying the wrong
detection multiplier; the level's torches confounding a distance measurement; a
death freezing `timeScale` and hanging the run) are structurally impossible here.
Exposure and speed are *arguments*.

- `ManiacBrainTests` — over `ManiacBrain.Score`. Split deliberately into
  **invariants** (fresh config: nothing may ever outrank a live chase; the
  breadcrumb grace window is protected; patrol is the floor when nothing is
  happening) and **shipped-config** guards that read `ManiacConfig.asset` and are
  *meant* to fail if someone detunes the game.
- `ManiacPerceptionTests` — over the pure statics `RateFor` / `StepAwareness` /
  `GuessErrorFor` / `HeardRadiusFor`. Pins the falloff curve as monotonic *and*
  usable, the blind spot behind him, point-blank ignoring facing, the awareness
  hold, the guess sharpening with certainty, and that he cannot outrun the player
  at a walk (this one reads `PlayerMovementConfig` too, so it breaks if either
  side moves). The hearing four (2026-08-02) guard the wall muffle in **both**
  directions: that every wall shortens the carry, that the shipped config muffles
  at all, that a wall is cover for walking but not for sprinting (reading the real
  `PlayerFootstepConfig` loudnesses), and that `hearingWallMuffle = 1` still
  reproduces the old geometry-blind hearing — the escape hatch has to be real.
- `ManiacChaseTests` (2026-08-02) — over `ChaseState.Stalled`. The arithmetic is
  trivial; what these guard is the **tuning**, which can silently break in two
  directions: a threshold so high that ordinary chasing reads as grinding (he
  paths through every chase and the relentless straight line is gone), or so low
  that a maniac stopped dead by a door frame never trips it. Also asserts the
  navigator takeover is shorter than `loseSightSeconds`, so the fallback stays a
  stumble rather than a change of character.
- Two guards were checked against the pre-fix config and provably fail on it —
  a suite that only ever passes is decoration.
- **Not covered here:** the 1s stare, the cone sweep, state transitions. Those
  need real frames, and that is where the one real bug of the pass actually lived
  (`Enter()` latching perception state). Until a PlayMode suite exists they are
  covered only by `TimeKiller/Verify/Probe Maniac Senses`.
